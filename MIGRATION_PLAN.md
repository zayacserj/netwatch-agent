# NetWatch — План миграции с Cloudflare KV на Raspberry Pi

## Текущее состояние
- Cloudflare Worker (`NetWatch_KV.txt`) + KV хранилище (ограничено квотами)
- Telegram бот (`/opt/netwatch/bot.py`) — команды: /start, /add_router, /routers, /devices, /settings, /guide, /history, /health, /admin
- HTTP API (`/opt/netwatch/api.py`) — события, устройства, health, раздача агента
- SQLite база данных (`/opt/netwatch/netwatch.db`) — таблицы: users, routers, devices, events, health_checks
- Caddy + Let's Encrypt на Pi (HTTPS через netwatchagent.duckdns.org)
- Агент `agent3.sh` на Pi, готов к установке на роутерах

### Проблемы, требующие решения:
1. DNS ROUTERS: netwatchagent.duckdns.org резолвится в локальный IPv6 (`fdf5:ec45:d241::1`) на роутере
2. SSL: роутер получает самоподписанный сертификат CN=OpenWrt (возможно, перехват TLS со стороны ISP)
3. Агент не загружается на роутере (Caddy возвращает 308 Redirect или 404 для /agent.sh)
4. SOLVED: Используем GitHub raw URL для доставки агента — обходит все проблемы DNS/HTTPS/Caddy для загрузки агента

### Решение (2026-10-30):
- Создан GitHub репозиторий: https://github.com/zayacserj/netwatch-agent
- Агент `agent3.sh` загружен в репозиторий, доступен по: https://raw.githubusercontent.com/zayacserj/netwatch-agent/main/agent3.sh

### Текущая проблема установки агента:
**Роутер не может загрузить agent.sh с Pi**
- DNS netwatchagent.duckdns.org резолвится в локальный IPv6 (`fdf5:ec45:d241::1`) вместо публичного IP (95.31.29.233)
- Проблема с SSL-сертификатом: роутер получает CN=OpenWrt (возможно, TLS-inspection ISP)
- Решение: установить DNS роутера на внешний (Google 8.8.8.8) + принудительное IPv4 + HTTP вместо HTTPS

**На роутере (TR3000):**
```bash
# 1. Сменить DNS роутера
uci set network.lan.dns=8.8.8.8
uci set network.lan.dns6=2001:4860:4860::8888
uci commit network
/etc/init.d/dnsmasq restart

# 2. Попробовать с HTTP (избежать проблем с HTTPS CN=OpenWrt)
curl -s http://95.31.29.233/agent.sh -o /tmp/agent3.sh
chmod +x /tmp/agent3.sh
/tmp/agent3.sh pair --code <CODE> --url http://95.31.29.233

# 3. Если нужно HTTPS (но нужно обойти TLS-inspection)
curl -sSk -4 https://95.31.29.233/agent.sh -o /tmp/agent3.sh
chmod +x /tmp/agent3.sh
/tmp/agent3.sh pair --code <CODE> --url https://95.31.29.233
```

**После регистрации роутера** (в любом случае), Pi не требует HTTPS для API (работает с HTTP), но предпочтительно использовать HTTPS (потребуется сертификат Pi).

## ⚠️ Риски и план отката

| Риск | Вероятность | План отката |
|------|-------------|-------------|
| Домашний интернет недоступен | Средняя | Вернуться на Cloudflare Worker временно |
| Pi выходит из строя | Низкая | Восстановить из бэкапа SD-карты или облачного бэкапа БД |
| Сертификат не обновляется | Средняя | Использовать самоподписанный сертификат на роутере (временный костыль) |
| Роутеры друзей не достучатся до Pi | Низкая | Использовать Cloudflare Tunnel или Tailscale |
| Установка агента на роутерах (проблемы с DNS/HTTPS) | Средняя | Использовать HTTP вместо HTTPS (требует изменения конфигурации Pi) |
