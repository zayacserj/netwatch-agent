# NetWatch — Документация по проекту

## 1. Пользовательская история

### Роли
- **Пользователь** — владелец одного или нескольких OpenWrt-роутеров, общается с ботом через Telegram
- **Telegram-бот** — интерфейс пользователя (команды: /start, /add_router, /routers, /devices, /settings, /guide, /history, /health, /admin)
- **Raspberry Pi (Хаб)** — центральный сервер: Telegram бот (long polling), HTTP API для агентов, SQLite БД, Caddy (HTTPS + Let's Encrypt)
- **OpenWrt-агент** (shell-скрипт `agent3.sh`) — крутится на роутере, собирает Wi-Fi/DHCP-клиенты, отправляет события в реальном времени, heartbeat, health-check
- **SQLite** — локальная база данных на Pi (пользователи, роутеры, устройства, события, health-check)

### Сценарии использования

#### 1. Подключение роутера
Пользователь пишет боту `/add_router` → получает pairing-код и команду для SSH на роутер → устанавливает агент одной командой → бот уведомляет: «Роутер подключён» и сразу выгружает все текущие Wi-Fi устройства в сети.

#### 2. Просмотр устройств
Пользователь пишет `/devices` → видит список всех Wi-Fi устройств, подключённых ко всем своим роутерам: имя, MAC, IP, к какому роутеру подключено, статус (онлайн/оффлайн), время последнего обнаружения. Может переименовать устройство.

#### 3. Просмотр роутеров
Пользователь пишет `/routers` → видит все свои роутеры со статусом онлайн/оффлайн, моделью, версией OpenWrt, временем последнего контакта.

#### 4. Уведомления
- Новое Wi-Fi устройство подключилось к сети → бот пишет в личку немедленно
- Устройство сменило статус (онлайн→оффлайн или оффлайн→онлайн) → уведомление (если включено для устройства)
- Роутер сменил статус → мгновенное уведомление в Telegram

#### 5. Управление уведомлениями
- Включить/выключить уведомления для конкретного устройства
- Включить/выключить уведомления для всех устройств сразу

#### 6. История событий
Пользователь пишет `/history` → видит историю всех Wi-Fi событий (подключения/отключения) за последние 24 часа по всем своим роутерам в одном потоке.

#### 7. Health-check роутеров
Пользователь пишет `/health` → видит статус здоровья всех своих роутеров: интернет, Wi-Fi, CPU, RAM, количество Wi-Fi клиентов, статус Podkop и тест подключения.

#### 8. Админ-консоль (только для владельца бота)
Пользователь (админ) пишет `/admin` → видит список всех пользователей бота, может удалить пользователя и очистить его данные (роутеры, устройства, события, health-check). Управление данными по конкретному пользователю.

- **`/admin list_users`** — список всех зарегистрированных chat_id (только для админа)
- **`/admin del_user <chat_id>`** — удалить пользователя и все его данные (роутеры, устройства, события)
- **`/admin clean_user <chat_id>`** — очистить данные пользователя (оставить chat_id, удалить роутеры, устройства, события, history, health-check)

#### 9. Логирование
- Агент пишет логи на роутер: в `/mnt/usb/log/netwatch/` если флешка подключена, иначе в `/etc/netwatch/logs/`
- При нескольких роутерах логи каждого хранятся в отдельном файле
- Логи ротации настраиваются через systemd/logrotate

### Масштаб
- До 10 уникальных пользователей (разные Telegram ID)
- Каждый пользователь: 1–5 роутеров (до 50 роутеров всего)
- На каждом пользователе: до 50 Wi-Fi клиентов (до 500 устройств всего)
- Проверка статуса: каждые 60 секунд (агент), health-check по расписанию

## 2. Целевая архитектура

### Стек технологий
- **Raspberry Pi 3b+** — центральный хаб (домой)
- **Python 3 + aiogram** — Telegram бот (long polling)
- **FastAPI** — HTTP API для агентов
- **SQLite** — локальная база данных на Pi
- **Caddy** — обратный прокси, автосертификат Let's Encrypt
- **DuckDNS** — `zayacserj.duckdns.org` → домашний IP
- **Telegram Bot API** — интерфейс пользователя
- **OpenWrt shell-скрипт** — агент на роутере (`agent3.sh`)
- **hostapd_cli** — события Wi-Fi в реальном времени
- **cron** на роутере — периодический запуск агента (каждые 60 секунд)

### Поток данных

**Регистрация роутера:**
1. Пользователь: `/add_router` → бот генерирует pairing-код + команду установки
2. Пользователь: `ssh root@роутер` → запускает команду установки агента
3. Агент: `pair` → регистрируется на Pi, получает `router_id`
4. Агент: `run` → отправляет список текущих Wi-Fi устройств
5. Pi: сохраняет роутер и устройства в SQLite
6. Бот: уведомляет пользователя, роутер онлайн, список устройств заполнен

**Периодический мониторинг (каждые 60 секунд):**
1. Агент: `run` → собирает Wi-Fi/DHCP клиенты, отправляет heartbeat + устройства на Pi
2. Pi: обновляет `seen_macs`, `last_seen`, `online` для роутера и устройств в SQLite
3. Pi: определяет новые устройства (MAC впервые появился) → отправляет уведомление в Telegram
4. Pi: определяет смену статуса устройства → отправляет уведомление (если включено)

**События в реальном времени (hostapd_cli):**
1. Агент: `wifi-monitor` подписывается на `hostapd_cli` события
2. При CONNECT/DISCONNECT → агент сразу шлёт POST /event на Pi
3. Pi: обрабатывает событие, обновляет БД, шлёт уведомление при необходимости

**Health-check (по расписанию):**
1. Агент: `health-check` → проверяет интернет, Wi-Fi, CPU, RAM, Wi-Fi клиенты, Podkop
2. Агент: шлёт POST /health на Pi
3. Pi: сохраняет результат в таблицу `health_checks`

**Просмотр состояния (команды бота):**
1. Пользователь: `/routers` → бот читает из SQLite и показывает роутеры
2. Пользователь: `/devices` → бот читает из SQLite Wi-Fi устройства
3. Пользователь: `/history` → бот читает из `events` за 24ч
4. Пользователь: `/health` → бот читает последние `health_checks`
5. Пользователь (админ): `/admin` → бот показывает сводку по всем роутерам

**Логирование:**
1. Агент пишет логи на роутер (флешка или каталог агента)
2. На Pi логи пишутся через systemd/journald

### API эндпоинты на Raspberry Pi

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/agent.sh` | Скачать скрипт агента для установки на роутер |
| POST | `/event` | Событие Wi-Fi connect/disconnect от роутера (JSON: router_id, mac, hostname, ip, event, timestamp, source) |
| POST | `/devices` | Снимок устройств от агента (cron) (JSON: router_id, devices[], timestamp) |
| POST | `/health` | Health-check от агента (JSON: router_id, internet, wifi, cpu, ram, wifi_clients, podkop_status, podkop_test, timestamp) |

**Защита:** Все эндпоинты требуют заголовок `X-Agent-Secret` (shared secret на роутер).

## 3. Хранение данных (SQLite на Pi)

### Таблицы:

**users** — пользователи Telegram
- `chat_id` (PK), `username`, `first_name`, `is_admin`, `created_at`

**routers** — зарегистрированные роутеры
- `router_id` (PK), `chat_id` (FK), `name`, `mac`, `model`, `openwrt_version`, `online`, `last_seen`, `created_at`

**devices** — кэш Wi-Fi устройств (только беспроводные)
- `mac`, `router_id` (PK), `ip`, `hostname`, `online`, `watch_online`, `label`, `first_seen`, `last_seen`

**events** — история событий (подключение/отключение Wi-Fi) для `/history`
- `id` (PK), `router_id` (FK), `mac`, `event`, `timestamp`

**health_checks** — результаты проверки здоровья роутеров
- `id` (PK), `router_id` (FK), `internet`, `wifi`, `cpu`, `ram`, `wifi_clients`, `podkop_status`, `podkop_test`, `timestamp`

## 7. Текущие проблемы и шаги к решению

### Проблема 1: DNS резолвинг netwatchagent.duckdns.org
На роутере TR3000 `netwatchagent.duckdns.org` резолвится в локальный IPv6 (`fdf5:ec45:d241::1`), что ведёт к подключению к самому роутеру вместо Pi.

**Решение:** Изменить DNS-серверы роутера на внешние:
```bash
uci set network.lan.dns=8.8.8.8
uci set network.lan.dns6=2001:4860:4860::8888
uci commit network
/etc/init.d/dnsmasq restart
```

### Проблема 2: TLS-inspection / SSL ошибка
При попытке HTTPS-соединения роутер получает самоподписанный сертификат с CN=OpenWrt (не `netwatchagent.duckdns.org`). Это может быть из-за TLS-inspection провайдера или из-за того, что DNS указывает на сам роутер.

**Обходное решение:** Использовать HTTP вместо HTTPS для первоначальной загрузки агента и пары:
```bash
curl -s http://95.31.29.233/agent.sh -o /tmp/agent3.sh
chmod +x /tmp/agent3.sh
/tmp/agent3.sh pair --code <CODE> --url http://95.31.29.233
```

### Проблема 3: Caddy отдаёт 404 для /agent.sh
На Pi файл `/var/www/netwatch/agent.sh` существует, но Caddy может не отдавать его по URL `/agent.sh`. Требуется проверить Caddyfile и перезапустить Caddy.

## 8. Команды для установки на роутере (справочник)

**После решения проблем с DNS/HTTPS:**

```bash
# На роутере TR3000 (под root)
# Вариант 1: HTTP (рекомендуется для пары, так как обходит SSL-инспекцию)
curl -s http://95.31.29.233/agent.sh -o /tmp/agent3.sh
chmod +x /tmp/agent3.sh
/tmp/agent3.sh pair --code <CODE> --url http://95.31.29.233

# Вариант 2: HTTPS с игнорированием проверки сертификата
curl -sSk -4 https://95.31.29.233/agent.sh -o /tmp/agent3.sh
chmod +x /tmp/agent3.sh
/tmp/agent3.sh pair --code <CODE> --url https://95.31.29.233
```

**После успешной регистрации:**
- Бот покажет "Роутер успешно зарегистрирован!"
- Роутер появится в `/routers`
- Устройства появятся в `/devices`
- Уведомления будут приходить в Telegram
