# Восстановление NetWatch на чистой Raspberry Pi

Сценарий для замены загрузочного носителя Raspberry Pi. Главный роутер TR3000 и точка доступа WR3000 остаются на месте. Их настройки и привязки агентов используются как есть.

На Windows эти шаги можно пройти с [NetWatch Pi Wizard](../outputs/NetWatch-Pi-Wizard.exe). Если выбрать архив Pi, мастер передаст его по SSH в закрытый каталог на Pi и восстановит настройки и данные из архива. Если выбрать «У меня нет архива», мастер установит встроенный NetWatch с пустой базой и запросит настройки на Pi. Для этого режима привязки роутеров создаются заново.

## 1. Загрузить чистую систему

Понадобятся загрузочный носитель с Raspberry Pi OS 64-bit на базе Debian 13 (Trixie) и отдельная USB-флешка с бэкапами. Если загрузочный носитель пустой, запишите ОС через Raspberry Pi Imager. Загрузите Pi и подключите её к TR3000 по Ethernet. Для установки зависимостей нужен интернет.

Перед восстановлением выключите старый экземпляр Pi, если он ещё работает. Так два процесса бота не будут одновременно использовать один токен.

Проверьте адрес командой `hostname -I`. В действующей сети Pi должна получить `192.168.1.10`. На этот адрес указывают локальный DNS и пробросы портов. Если меняется только загрузочный носитель, DHCP-резервация для того же Ethernet-интерфейса должна выдать прежний адрес.

## 2. Подключить USB и проверить архив

Подключите USB с бэкапами. Найдите его раздел через `lsblk -f` и смонтируйте в `/mnt/netwatch-backup`. На нём должны быть каталоги `restore-kit` и `netwatch-backups`.

Выберите нужный архив и подставьте его точное имя вместо `ARCHIVE.tar.gz`.

```bash
sudo sh /mnt/netwatch-backup/restore-kit/restore.sh \
  /mnt/netwatch-backup/netwatch-backups/ARCHIVE.tar.gz
```

Команда проверяет архив и распаковывает его в каталог подготовки.

## 3. Развернуть NetWatch

После успешной проверки запустите установку на чистой Pi.

```bash
sudo sh /mnt/netwatch-backup/restore-kit/restore.sh \
  /mnt/netwatch-backup/netwatch-backups/ARCHIVE.tar.gz --apply
```

Скрипт устанавливает зависимости, восстанавливает код, настройки и базы SQLite, затем запускает Caddy, NetWatch API, Telegram-бота и веб-монитор. Бот использует токен из архива. Привязки роутеров восстанавливаются из базы, поэтому на TR3000 и WR3000 повторно выполнять `/add_router` не нужно. Данные и настройки возвращаются на момент создания выбранного бэкапа.

## 4. Проверить сервисы и включить ежедневные бэкапы

```bash
systemctl is-active caddy netwatch-api netwatch-bot netwatch-monitor
```

Вызовите `/health` в Telegram и убедитесь, что оба роутера присылают свежие отчёты. Откройте веб-монитор из внешней сети и проверьте вход и обновление показателей.

Настройте постоянное монтирование USB по UUID в `/mnt/netwatch-backup`. Запустите ручной бэкап и проверьте по журналу, что USB-копия прошла проверку.

```bash
sudo systemctl start netwatch-backup.service
journalctl -u netwatch-backup.service -n 30 --no-pager
```

Перед включением таймера проверьте расписание на 02:00 по времени Pi и срок хранения 30 дней. Эти настройки включены в USB-комплект, обновлённый 9 ноября 2026 года из коммита `4777884`.

Затем включите ежедневный таймер.

```bash
sudo systemctl enable --now netwatch-backup.timer
systemctl list-timers netwatch-backup.timer
```

Создание USB-копии, проверка целостности и распаковка архива уже подтверждены на действующей Pi. Полный запуск с `--apply` на чистом носителе ещё предстоит испытать.

## Отложенная проверка Wizard

Проверенный архив для режима с данными — `/mnt/netwatch-backup/netwatch-backups/netwatch-20261109T104641809543Z-91bf6638.tar.gz`. Если испытание пройдёт позже, можно выбрать более свежий архив с USB. При хранении 30 дней этот архив со временем будет удалён по расписанию.

- [ ] Сергей — найти запасную microSD, записать чистую Raspberry Pi OS 64-bit (Debian 13 / Trixie), включить SSH и сообщить, когда носитель готов.
- [ ] Вместе — испытать на запасной microSD оба режима Wizard. Для каждого запуска начать с чистой ОС. Проверить запуск API, Telegram-бота и веб-монитора. В режиме с архивом также проверить историю и действующие привязки, а в режиме без архива — создание новой привязки.

См. также [руководство по эксплуатации NetWatch](NetWatch.md).
