# Веб-монитор Raspberry Pi

Служба использует Python 3 из системы и отдаёт страницу и JSON со свежим
снимком. Она слушает только `127.0.0.1:8090`. Снимки хранятся в памяти.
Интерфейс запрашивает данные раз в пять секунд и помечает потерю связи.

## Локальная проверка на Pi

Из каталога с файлами монитора:

```bash
python3 -B pi_monitor.py
```

Из второго терминала Pi:

```bash
curl --fail --silent --show-error http://127.0.0.1:8090/monitor/api/v1/metrics
```

Для просмотра на компьютере откройте SSH-туннель:
`ssh -N -L 8090:127.0.0.1:8090 <пользователь>@<адрес-Pi>`.
Затем откройте `http://127.0.0.1:8090/monitor/`.

Системный раздел отображается автоматически. Дополнительный накопитель
можно добавить параметром `--mount /путь/к/разделу` после проверки точки
монтирования. Контейнеры Docker и Podman отображаются по коротким ID,
если их запущенные cgroup v2 доступны для чтения. Службе не нужен сокет Docker.

## Подключение к NetWatch

После локальной проверки файлы размещаются в `/opt/netwatch/monitor`,
а unit-файл — в `/etc/systemd/system/netwatch-monitor.service`.
Сначала проверьте службу локально и измерьте CPU и память. Затем добавьте
маршрут из `Caddyfile.example` внутрь HTTPS-блока NetWatch. Проверяйте и
страницу, и `/monitor/api/v1/metrics`: без логина оба должны возвращать 401.
После успешной проверки HTTPS ссылку можно добавить в кнопку «Мониторинг Pi»
в Telegram. Пароль, его хеш и реальная конфигурация Caddy хранятся на Pi.
