# Резервное копирование NetWatch

В рабочем архиве есть обе базы SQLite, если они существуют, действующие
файлы бота, API, веб-монитора, конфигурация приложения и Caddyfile. В архив
также входят unit-файлы и drop-in конфигурации четырёх служб. Копии баз
снимаются через SQLite Backup API при работающих службах. Архив становится
виден после проверки SHA-256 всех файлов и открытия обеих баз, извлечённых
во временный каталог. Это копия приложения, а не образ microSD.

Локальный каталог — `/opt/netwatch/backups/scheduled`. Доступ к нему нужен
только root: архив содержит секреты приложения. Скрипт не читает содержимое
баз для журнала. TLS-кеш Caddy, пакеты ОС и файлы конфигурации OpenWrt
не входят в этот архив. Для восстановления Caddy получает сертификат через
действующий DNS и HTTPS, а настройки OpenWrt сохраняются отдельно.

## Запуск и проверка

```bash
python3 -IB /usr/local/lib/netwatch/backup_netwatch.py create
python3 -IB /usr/local/lib/netwatch/backup_netwatch.py verify /путь/к/netwatch-*.tar.gz
```

В команду `verify` передаётся путь к одному конкретному архиву.
Она ничего не меняет в рабочей базе. После первого ручного запуска можно
включить `netwatch-backup.timer` на 03:20 по местному времени Pi.
Результаты доступны через `journalctl -u netwatch-backup`.

## Копия на USB

В защищённом файле `/etc/netwatch-backup.conf` задаются:

```ini
NETWATCH_USB_MOUNT=/mnt/netwatch-backup
NETWATCH_USB_UUID=UUID_НОСИТЕЛЯ
NETWATCH_BACKUP_KEEP=14
```

Нужен смонтированный носитель с заданным UUID. USB-архивы содержат
конфигурацию и секреты приложения в открытом виде. Храните носитель
в месте с ограниченным физическим доступом.
Если носитель отсутствует, локальный архив сохраняется, а пропуск USB
фиксируется в журнале. Архив на USB получает окончательное имя только
после записи и проверки SHA-256.
Локальная ротация действует на архивы самого скрипта после успешного
копирования, если USB настроен. При `NETWATCH_BACKUP_KEEP=0` ротация
отключена. На USB удаление старых файлов выполняется отдельно.

Для контрольного восстановления передайте путь к архиву на USB
в команду `verify`. Она проверит контрольные суммы и целостность
извлечённых копий SQLite.

## Подготовка к восстановлению

```bash
python3 -IB /usr/local/lib/netwatch/backup_netwatch.py prepare-restore /путь/к/архиву.tar.gz
```

Команда проверяет целостность архива, наличие файлов NetWatch и веб-монитора,
статического каталога Caddy и версий Python-пакетов. Она извлекает файлы
в отдельный каталог с доступом только для владельца. Рабочая система
на этом этапе не меняется. Для этого режима нужен архив, сделанный после
добавления профиля восстановления.

## Установка из архива на чистую Pi

Комплект восстановления состоит из `restore.sh`, `restore_netwatch.py`,
`backup_netwatch.py`, `netwatch-backup.service`, `netwatch-backup.timer`
и `netwatch-monitor.service` из репозитория NetWatch. Положите эти файлы
в один каталог, например `restore-kit` на USB рядом с `netwatch-backups`.
Используйте проверенный комплект из GitHub.

На чистой Debian/Raspberry Pi OS 13 arm64 с интернетом и Python 3.13
сначала проверьте выбранный архив:

```bash
sudo sh /путь/к/restore-kit/restore.sh /путь/к/архиву.tar.gz
```

Для применения на чистой Pi выполните ту же команду с `--apply`:

```bash
sudo sh /путь/к/restore-kit/restore.sh /путь/к/архиву.tar.gz --apply
```

Перед применением выключите исходную Pi, чтобы один токен Telegram
обслуживала только одна копия бота. Скрипт отказывается заменять уже
существующую установку. Он ставит зависимости, Caddy из официального
репозитория и Python-пакеты в отдельное виртуальное окружение, восстанавливает
файлы и базы и запускает API, бот, монитор и Caddy. Код принадлежит root,
а рабочая SQLite хранится в отдельном каталоге `/var/lib/netwatch`.
В конфигурации Caddy сохраняется защита монитора логином и паролем.

После локальной проверки проверьте внешний HTTPS и ответ `/health` в
Telegram. Для этого должны работать DNS и проброс TCP 443 на восстановленную
Pi. Для теста установки можно подготовить отдельный загрузочный носитель
и сначала проверить архив без `--apply`.

Комплект восстанавливает файлы службы бэкапа, таймера и её настройки.
После проверки UUID и монтирования USB запустите службу вручную, затем
включите таймер. Конфигурация загрузочного носителя и `/etc/fstab` новой ОС
настраиваются отдельно. Если применение остановилось с ошибкой, сохраните
вывод и путь к каталогу подготовки. Повторный запуск поверх частично
установленных файлов блокируется.
