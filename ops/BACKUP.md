# Резервное копирование NetWatch

В рабочем архиве есть обе базы SQLite, если они существуют, действующие
файлы бота, API, веб-монитора, конфигурация приложения и Caddyfile. В архив
также входят unit-файлы и drop-in конфигурации четырёх служб. Копии баз
снимаются через SQLite Backup API при работающих службах. Архив становится
виден после проверки SHA-256 всех файлов и открытия обеих баз, извлечённых
во временный каталог. Это копия приложения, а не образ microSD.

Локальный каталог — `/opt/netwatch/backups/scheduled`. Доступ к нему нужен
только root: архив содержит секреты приложения. Скрипт не читает содержимое
баз для журнала. TLS-кеш Caddy, пакеты ОС и файлы конфигурации OpenWrt
не входят в этот архив. Для восстановления Caddy получает сертификат через
действующий DNS и HTTPS, а настройки OpenWrt сохраняются отдельно.

## Запуск и проверка

```bash
python3 -B /opt/netwatch/ops/backup_netwatch.py create
python3 -B /opt/netwatch/ops/backup_netwatch.py verify /путь/к/netwatch-*.tar.gz
```

В команду `verify` передаётся путь к одному конкретному архиву.
Она ничего не меняет в рабочей базе. После первого ручного запуска можно
включить `netwatch-backup.timer` на 03:20 по местному времени Pi.
Результаты доступны через `journalctl -u netwatch-backup`.

## Копия на USB

В защищённом файле `/etc/netwatch-backup.conf` задаются:

```ini
NETWATCH_USB_MOUNT=/mnt/netwatch-backup
NETWATCH_USB_UUID=UUID_НОСИТЕЛЯ
NETWATCH_AGE_RECIPIENT=age1_ПУБЛИЧНЫЙ_КЛЮЧ
NETWATCH_BACKUP_KEEP=14
```

Нужен пакет `age` и смонтированный носитель с заданным UUID. На Pi хранится
только публичный ключ, закрытый ключ хранится отдельно от Pi и USB.
Если носитель отсутствует, локальный архив сохраняется, а пропуск USB
фиксируется в журнале. На USB создаются только зашифрованные архивы.
Локальная ротация действует на архивы самого скрипта после успешного
копирования, если USB настроен. При `NETWATCH_BACKUP_KEEP=0` ротация
отключена. На USB удаление старых файлов выполняется отдельно.

Для контрольного восстановления расшифруйте один файл `.age` на доверенном
компьютере с закрытым ключом и проверьте полученный `.tar.gz` командой
`verify`. Храните расшифрованную копию в закрытом каталоге. Копия считается
готовой к использованию после проверки расшифровки и целостности SQLite.
